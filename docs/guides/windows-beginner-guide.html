The big picture

You are setting up a creative writing workspace that comes pre-loaded with an AI team: a Story Architect, a Dialogue Writer, a Script Supervisor, and eight more specialists. You talk to them in plain English, and they help you write and format a professional screenplay.

Four tools each do one small job. Here is the whole system at a glance.

The one idea that makes this easy

The Claude Code tab is not only a chat box. It can run the setup steps for you. So instead of learning commands, you open your project and type something like "install the dependencies and initialize this project as a screenplay named my-first-script." Claude does it while you watch.

Your computer:

  • About 2 to 3 GB free disk space and an internet connection.

Part A

Install the four tools (once)

Do these five short steps in order. You never repeat Part A. Once these are on your PC, you are set for every future project.

A1. Get a paid Claude plan (required)

  1. In a browser, go to claude.ai and sign up (or log in) with your email.
  2. Go to claude.com/pricing and subscribe to Claude Pro (recommended to start) or Claude Max.
  3. That is it. The same login works in the desktop app you install next.
Why this comes first

If the plan is not active, later steps still look like they work, but the Code tab will not open. Getting it out of the way now saves confusion.

A2. Install the Claude desktop app

This is where your AI team works. It includes Claude Code built in, with a graphical interface, so no terminal is required.

  1. Go to claude.com/download and click the Windows download. A file like Claude-Setup.exe lands in your Downloads folder.
  2. Double-click it and follow the installer. You do not need to be an administrator.
  3. Open Claude from the Start menu and sign in with the account you paid for in A1.
  4. At the top you will see three tabs: Chat, Cowork, and Code. You will use Code later. If clicking Code asks you to upgrade, your paid plan is not active yet, so fix that first.

A3. Install Node.js (required)

Node.js is a small free tool the template uses behind the scenes to check formatting and spelling. Install once, forget forever.

  1. Go to nodejs.org.
  2. Click the big LTS button, which means "the stable version" (for example "20.x.x LTS"). A .msi file downloads.
  3. Double-click it, then click Next, Next, Install. The defaults are correct, so change nothing, then click Finish.
Normal

You will not see a new app in your Start menu, which is normal. Node.js works quietly in the background. It is separate from Claude. The Claude app has its own copy of Claude Code, but the template's helper tools need this one.

A4. Install Git for Windows (required)

Git is the technology GitHub is built on. Claude's Code tab needs it installed to work on files on your PC (a "Local" session).

  1. Go to git-scm.com/downloads/win and click 64-bit Git for Windows Setup.
  2. Double-click the download. The installer asks a lot of questions. You can safely click Next on every screen and accept all defaults, then Install, then Finish. None of the options matter here.

A5. Make a GitHub account and install GitHub Desktop

GitHub stores the template and, later, backs up your work. GitHub Desktop does all the GitHub steps with buttons instead of commands.

  1. Create a free GitHub account: go to github.com/signup and follow the prompts. It is free.
  2. Install GitHub Desktop: go to desktop.github.com, click Download for Windows, then double-click GitHubDesktopSetup.exe.
  3. Open GitHub Desktop and sign in with your new GitHub account. If a browser opens to confirm, click Authorize.
End of Part A: checklist

You should now have: a paid Claude plan, the Claude app (signed in), Node.js, Git for Windows, a GitHub account, and GitHub Desktop (signed in). All five done? You never touch Part A again.

Part B

Make your own copy of the template

You do not write inside the shared template. You make your own private copy first. GitHub has a one-click button for exactly this.

  1. In your browser, open the template page: github.com/bybren-llc/story-systems-template
  2. Near the top-right, click the green Use this template button, then choose Create a new repository. ("Repository," or "repo," is just GitHub's word for one project folder.)
  3. On the "Create a new repository" screen:
    • Repository name: your project name in all lowercase with hyphens instead of spaces, for example my-first-script or midnight-diner. See the Naming cheat-sheet, because this matters.
    • Owner: leave it as your username.
    • Public or Private: choose Private to keep your script to yourself (recommended for creative work).
    • Leave "Include all branches" unchecked.
  4. Click Create repository. After a few seconds you will see your copy at github.com/YOUR-USERNAME/my-first-script.
What just happened

You now own a complete, private copy of the whole AI-writing template. The original stays untouched, and you will only ever change your copy.

Part C

Download your project to your PC

Your project lives online right now. To write on your computer you "clone" it, which is GitHub's word for downloading a working copy. GitHub Desktop does it in two clicks.

  1. On your new repository's page, click the green < > Code button, then Open with GitHub Desktop. If the browser asks "Open GitHub Desktop?", click Open.
  2. In the Clone a repository window, the Local path is where the folder will live (the default, like C:\Users\YourName\Documents\GitHub\my-first-script, is fine). Remember this location, because that is where your screenplay lives. Click Clone.
  3. If asked how you are planning to use this repository, choose For my own purposes, then Continue.
No terminal needed

GitHub Desktop ran git clone for you. To find the folder later, click Repository, then Show in Explorer in GitHub Desktop. Keep GitHub Desktop open, because you will use it again in Part G.

Part D

Open your project in Claude

Now we bring in your AI team.

  1. Open the Claude desktop app from the Start menu.
  2. Click the Code tab at the top center.
  3. When asked how to run, choose Local, which means "work on the files on my own PC."
  4. Click Select folder and choose the folder from Part C, for example C:\Users\YourName\Documents\GitHub\my-first-script.
  5. Near the send button is a model dropdown. The default is fine, and you can change it later.
You are always in control

The Code tab starts in Manual mode. Claude shows you every change and waits for your Accept or Reject before anything happens to your files. Nothing is edited or run without your OK.

Part E

Set up your project

Your folder is a fresh copy of the template. Two small things happen once: install the helper tools, and "initialize" the project, which names it and creates your blank screenplay file. You will not type commands. You ask Claude.

The easy way: ask Claude

In the message box at the bottom of the Code tab, paste this (change the name to your project, using lowercase with hyphens) and press Enter:

Type this to Claude
Please set up this project for me. First run "npm install" to install the
dependencies, then run the Windows initializer script to initialize it as a
screenplay project named my-first-script. Show me each command before you run it.

Claude proposes running npm install and then the setup script (.\scripts\init-project.ps1). Because you are in Manual mode, it shows each step and waits, so click Accept or Run to let each proceed. When it asks the project type, the answer is screenplay (option 1), the only type ready today.

When it finishes, Claude will have created your personal files, including:

  • my-first-script.fountain, your actual screenplay (it starts almost blank, ready for you).
  • templates/beat-sheet.md and templates/character-registry.md, your planning docs.
  • A personalized README.md and project settings carrying your project's name.
About the name you chose

Setup turns your hyphenated name into two things: my-first-script becomes the file my-first-script.fountain, and the on-screen title "My First Script" (each word capitalized). That is why the name should be lowercase with hyphens. See the Naming cheat-sheet.

If you see "CLAUDE.md (copy: symlink requires Developer Mode)"

Normal, harmless Windows message. Everything works exactly the same, so you can ignore it.

The manual way, only if you would rather do it yourself

You can run the two steps in the app's built-in terminal:

  1. Open the integrated terminal with Ctrl + ` (the backtick key, top-left under Esc).
  2. Type npm install and press Enter.
  3. When done, run the initializer:
PowerShell: initialize the project
.\scripts\init-project.ps1

If Windows blocks it with a red "execution policy" message, use this instead:

PowerShell: if blocked by execution policy
PowerShell -ExecutionPolicy Bypass -File .\scripts\init-project.ps1

It asks for a project name (type your lowercase-hyphenated name, press Enter) and a project type (press Enter to accept screenplay). The easy way above is what this system is designed for, so letting Claude run the setup is the intended experience.

Part F

Start writing

Your AI team is ready. You steer it two ways, both in the same message box.

1. Slash commands (type /)

Type a forward slash / and a menu of commands pops up (or click +, then Slash commands). A few to start with:

Type thisWhat it does
/start-scene A tense diner argument at midnightBegins a new scene with the right setup
/writers-roomConvenes the AI team to brainstorm before you write
/check-formatChecks your screenplay is correctly formatted
/scene-listLists every scene with a page estimate
/export-pdfTurns your script into a professional PDF
/stuckLooks at where you are and suggests what to do next
New to all this?

Type /stuck, or just say in plain English: "I'm new here, help me start my first scene." The AI team is built to guide beginners.

2. Plain English

You do not have to use commands at all. You can simply type things like:

  • "Help me brainstorm a logline for a heist movie set in a bakery."
  • "Write an opening scene: a lighthouse keeper finds a message in a bottle."
  • "Read my beat sheet and tell me if Act Two is too slow."

Every change Claude makes to a file is shown to you first, in the diff view with Accept and Reject buttons. Nothing happens to your screenplay without your approval.

Part G

Save your work back to GitHub

As you write, changes live on your PC. To keep a safe online backup, and to be able to work from another computer later, save them back to GitHub. There are two easy ways.

Easiest: ask Claude

Type this to Claude
Please save my work: commit these changes with a short message describing
them, then push to GitHub.

Or use GitHub Desktop (buttons only)

  1. Switch to GitHub Desktop. On the left you will see the files you changed.
  2. Bottom-left, type a short note in the Summary box, for example "Wrote opening diner scene."
  3. Click Commit to main. Commit means "save a snapshot."
  4. Click Push origin at the top. Push means "upload the snapshot to GitHub."
Do this whenever you finish a session

It is your undo history and your backup in one. If your PC ever dies, your screenplay is safe on GitHub. To come back tomorrow: open Claude, click the Code tab, and your project is remembered (or click Select folder again). That is the 10-second daily routine.

Naming cheat-sheet (important)

Getting names right up front avoids confusing errors later. There are three names, and the simplest life is to make them all the same lowercase-hyphenated word.

WhereWhat to typeGoodAvoid
GitHub repo name (Part B)Your project namemidnight-dinerMidnight Diner
Local folder name (Part C)Usually auto-matches the repomidnight-dinerspaces, symbols
Project name in setup (Part E)The same word againmidnight-dinerMidnight Diner

The golden rules for the project name:

  • Yes: all lowercase, for example midnight-diner.
  • Yes: hyphens (-) instead of spaces, so not midnight diner.
  • Yes: letters and numbers only, so no ! @ . ' /.
  • No: no spaces, no capitals, no punctuation.
Why it matters

Enter midnight-diner and setup creates the file midnight-diner.fountain and sets your screenplay's display title to "Midnight Diner" (capitalized for you). You can change the on-screen title later inside the .fountain file. The folder and file name are simplest to just get right once.

Troubleshooting

Common first-timer bumps on Windows, and the fix for each.

The "Code" tab tells me to upgrade.
Your paid Claude plan is not active. Revisit A1, subscribe to Pro or Max at claude.com/pricing, then restart the Claude app.

"Select folder" or the Local session will not start, or it mentions Git.
Git is not installed. Do A4, then fully close and reopen the Claude app.

npm is not recognized, or "npm is not installed."
Node.js is not installed, or the app was open before you installed it. Do A3, then completely close and reopen the Claude app so it sees the new tool, and try Part E again.

The setup script is blocked by a red "execution policy" message.
Windows being cautious. Use this version (Claude can run it for you):

PowerShell
PowerShell -ExecutionPolicy Bypass -File .\scripts\init-project.ps1

I see "CLAUDE.md (copy: symlink requires Developer Mode)."
Normal on Windows, and the copy works identically, so there is nothing to fix. If you want the tidier version, Settings, then System, then For developers, then Developer Mode: On enables it, but it is purely cosmetic.

"git is not recognized" in the terminal.
Git was installed but the app was already open. Close and reopen the Claude app (and GitHub Desktop) so they pick up Git.

A command seems stuck, or I am lost.
In the Code tab, type in plain English: "that didn't work, here's what I see: [paste the message]. What should I do?" Claude reads the message and walks you through it.

I accidentally changed something I did not mean to.
Nothing is permanent until you commit (Part G). In GitHub Desktop, right-click a changed file, then Discard changes to undo it.
